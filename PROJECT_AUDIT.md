# DialectDuel: аудит і план переробки

Дата: 2026-10-08. Звіт описує поточну робочу копію, включно з незакоміченими змінами. Реалізацію застосунку в межах аудиту не змінено.

Переглянуто всі Dart-файли в `lib/`, тест, залежності, Android/iOS-конфігурацію та використання зображень. `flutter analyze --no-pub` завершився з `No issues found`. Усі 18 очікуваних портретів існують. Поведінку анімації та завершення TTS додатково звірено з локальним кодом встановлених пакетів. Застосунок на телефоні та живі запити до Gemini не перевірялися. Це перелік знайдених дефектів і ризиків, а не гарантія відсутності інших.

P1 — виправити перед редизайном; P2 — виправити під час переробки; P3 — додаткове покращення. Посилання на рядки — для цієї версії файлів.

## 3. Заглушки й незавершені функції

- **Лідерборд:** вигадані учасники, незмінне 4-те місце гравця, XP щонайменше 3180 навіть у нового профілю, статичні ліга й «2 дні». `leaderboard_screen.dart:51,98,110`.
- **Профіль:** фіксовані Олена/@olena_boss, рік вступу, ліга, 9 місць у топ-3 й досягнення без перевірки умов. Реальні лише XP та streak. `profile_screen.dart:67,87,127,144`.
- **Акаунт:** вигадані ім'я/email, рядки зі стрілками без дії, кнопка виходу без onTap, автентифікації немає. `settings_screen.dart:129,147,221`.
- **Налаштування:** SFX-перемикач лише зберігає bool, звукового відтворення немає. Auto-send, UI language, accent та voice зберігаються сервісом, але не підключені до поведінки застосунку. TTS speed читається грою, але не редагується на екрані налаштувань; дефолт 1.0 перекриває 0.55 із сервісу.
- **Історія:** немає збережених сесій, перемог/поразок за сценаріями, тривалості практики або історії виправлень. Це потрібно для справжнього екрана прогресу.
- **Мертвий код:** GameHud, MicButton і NpcFullBackground не використовуються активними екранами. Два варіанти avatar дублюють мапінг емоцій. Не створювати третю незалежну реалізацію.
- **Тести:** `test/widget_test.dart` перевіряє лише `expect(true, isTrue)`; проходження цього тесту не свідчить про роботу застосунку. Поточний lockfile вимагає Flutter >=3.38.4, тому «Flutter з Dart 3» у README недостатньо точна вимога.

## 4. Що переробити за ідеями користувача

### Вибір персонажа свайпом

Замінити вертикальні Unit-блоки на горизонтальний PageView з великими картками. Картка: портрет, ім'я, роль, конкретна задача гравця, складність, особистий результат. Додати індикатор сторінки і стрілки як альтернативу свайпу. Один CTA «Почати розмову» запускає саме видимого персонажа. Перегортання не робить AI-запитів. Зберігати останнього обраного героя.

### NPC починає сам

Ця поведінка вже задумана кодом, але B02/R02 роблять її ненадійною. Показувати авторську вступну репліку відразу після входу; за потреби використовувати AI-вступ з коротким таймаутом і fallback того самого персонажа. Це повноцінний контент сценарію. TTS ініціалізувати незалежно, дозвіл мікрофона запитувати при першому натисканні. Ввід відкривається після появи вступу. Невдале озвучення не блокує текстову гру.

### Емоції як частина розмови

Уже є дев'ять емоцій і дев'ять PNG для кожного героя. Нині портрет лише 90×110 і стоїть першим елементом списку чату: після прокручування реакцій не видно. NpcFullBackground з переходами існує, але не підключений.

Зробити постійно видиму сцену персонажа над діалогом; при клавіатурі вона компактно зменшується. Розділити настрій (`neutral/happy/angry/...`) і стан взаємодії (`idle/listening/thinking/speaking`). Емоція має випливати з репліки й ситуації: вдала аргументація → зацікавлення/схвалення, суперечність → здивування/сумнів, агресія → злість. Звичайна граматична помилка не повинна автоматично викликати крайню реакцію.

Плавно міняти портрет за 200–350 мс, попередньо завантажувати зображення. Окремо короткий акцент для сильних реакцій, спокійний idle, індикатор слухання й озвучення. Зберігати емоцію та feedback у кожному ході. Додати перевірений fallback для невідомої емоції й підтримати зменшення анімацій. Нові типи емоцій додавати після того, як усі поточні працюватимуть доречно й будуть видимі.

### Меню без заглушок

Пропонована навігація: **Персонажі / Мій прогрес / Профіль**.

| Екран | Справжні дані й дії |
|---|---|
| Персонажі | Картки свайпом, реальні сценарії, останній/найкращий результат, старт |
| Мій прогрес | Історія завершених розмов, XP, перемоги, календар практики, збережені виправлення |
| Профіль | Локально редаговане ім'я й аватар, дата першого запуску, досягнення за реальними умовами |
| Налаштування | Тема, озвучення, доступні голоси, швидкість із прослуховуванням, підтвердження відправки транскрипту; кожний перемикач впливає на поведінку |
| Результат | Назва сценарію, підсумок, зміни показників, конкретні виправлення, «Ще раз» та «До персонажів» |

Поки немає сервера, прибрати фіктивну лігу, пошту, вихід з акаунта й чужі результати. Якщо онлайн-рейтинг потрібен як продуктова функція, реалізувати його окремим етапом з акаунтами та серверним підтвердженням XP. Порожній новий профіль показує чесний стан «Ще немає завершених розмов» і кнопку старту.

Візуально: персонаж і поточна репліка — головні елементи; стримані поверхні, окремий акцент для кожного героя, одна система відступів/радіусів/кнопок, дві читабельні шкали. Використовувати кольори теми, дати підписи нижній навігації й accessibility labels кнопкам, не покладатися лише на колір для настрою/результату. Інтерфейс локалізувати послідовно, репліки для практики залишити англійськими.

## 5. Порядок реалізації та критерії готовності

1. **Стабільний цикл розмови:** B01–B05, B08–B13, R01–R03. Винести orchestration з GameScreen у контролер сесії; інжектувати AI/STT/TTS для перевірок. Стани запуску/очікування/запису/запиту/озвучення/завершення, session/turn ID, однократне збереження результату.
2. **Єдині правила й дані:** конфігурації персонажів, валідація AI-відповіді, локальний підрахунок балів, одна механіка сердець, streak за завершеним уроком, збережена історія SessionResult/TurnRecord. Уникати додаткового state-management фреймворку лише заради цієї зміни.
3. **Сцена й свайп:** PageView, портрет завжди видно, осмислені реакції, автоматичний вступ, синхронізовані голосові стани.
4. **Реальне меню:** заміна заглушок на локальні дані, робочі дії профілю/налаштувань, адаптивна верстка й теми.
5. **Перевірки змінених сценаріїв:** історія залишається видимою після 5+ ходів; HR зберігається після повтору; NPC починає без доступу до мікрофона; таймаут має повтор без дубля; WIN/LOSE записується один раз навіть при виході/TTS-помилці; немає setState після dispose; STT правильно зупиняється; календарні дні/DST; малий екран, клавіатура, великий шрифт і темна тема. Реальні STT/TTS перевірити на Android та iOS.

Починати з логіки розмови: красивіший екран поверх поточних станів успадкує ті самі зависання, дублювання й втрату результатів.
